## Context

见 `proposal.md`。现有 AI 能力只有行程生成（非流式）与游记润色（SSE 流式）；国家抽屉由 `MapService` 提供本人数据。前端已有基于 `fetch` + `ReadableStream` 的 SSE 解析实现（`api/ai.ts`），本次沿用同一协议风格。

## Goals / Non-Goals

**Goals:**

- 按国家生成并缓存三块攻略，缓存命中零额度、零 LLM 调用。
- 复用现有额度、SSE、Redis、LLM 抽象，不引入新基础设施。
- 行程生成彻底停止产出与缓存行前准备。

**Non-Goals:**

- 不提供用户自行编辑攻略或手动刷新缓存（24 小时后自然过期）。
- 不按用户、城市或偏好生成个性化攻略。
- 不新增数据库表或 Flyway 迁移。
- 不接入搜索/官方链接；抽屉已有官方链接能力保持不变。

## Decisions

1. **流式输出采用固定 Markdown 章节，服务端解析为结构化结果**
   - Prompt 要求模型按 `## 国家介绍`、`## 推荐景点`、`## 旅游须知` 输出；`推荐景点` 使用 `- 名称：描述`，`旅游须知` 使用 `- 签证：`、`- 货币：`、`- 插头：`、`- 最佳季节：`、`- 提示：`。
   - 服务端逐块转发原始文本作为 `delta`，结束后解析为 `intro/attractions/notice`，随 `done` 事件返回。
   - 备选：让模型流式输出 JSON。JSON 在流中不可逐步渲染，且容易因尾部未闭合导致体验差，故不采用。
   - 备选：非流式生成后由前端模拟打字。无法满足首字延迟要求，故不采用。

2. **缓存键 `country-guide:v1:{CODE}`，TTL 24 小时，全局共享**
   - 键带版本号，提示词或解析结构变化时提升版本即可整体失效。
   - 缓存命中在额度检查之前返回，不扣费；这是“按国家缓存”的直接结果，也避免同一国家被重复计费。
   - 备选：按用户缓存。会放大成本且内容完全相同，不采用。

3. **两个接口：读取缓存与流式生成分离**
   - `GET /api/country-guide/{countryCode}` 返回 `{available, guide}`，供抽屉打开时静默加载缓存。
   - `POST /api/country-guide/stream` 接收 `{requestId, countryCode}`；命中缓存时发送 `meta(cached=true)` + `done(guide)`，未命中时扣费并流式生成。
   - 备选：抽屉打开即调用 POST。会在无缓存时误触发生成，与“点击才生成”冲突，不采用。

4. **同国并发用 Redis `SETNX` 锁，锁 TTL 180 秒**
   - 拿锁前与拿锁后各查一次缓存；拿不到锁且仍无缓存时返回 `3001`「该国攻略正在生成」。
   - 锁只保护 LLM 调用，不参与缓存读取；`finally` 中释放。
   - 备选：不加锁。会重复扣费并放大 LLM 成本，不采用。

5. **额度与退款沿用现有 `QuotaService` 语义**
   - 扣费来源 `FREE/PACK/VIP` 通过 `meta.quotaSource` 返回；缓存命中为 `CACHE`。
   - 以“是否发送过 `delta`”判断退款：未发送即失败或断开退回，已发送则不退；`refund` 本身幂等。

6. **LLM 抽象新增 `guideStream`，与 `polishStream` 共用 HTTP 流式实现**
   - `HttpLlmProvider` 抽出私有 `streamChatCompletion(prompt, onDelta, cancelled)`，两种能力只差异在提示词与超时。
   - 攻略流式超时 120 秒，与润色一致。

7. **行前准备优雅下线**
   - `PromptBuilder` 删除 `preparations` 的 Schema 与要求；`ItineraryGenerationService` 删除解析、缓存与 `prep:*` Redis 键，响应固定返回空 `Preparations`。
   - 保留 `preparations` DTO 字段与数据库列，历史行程详情仍可读；`PlanView` 仅在字段非空时渲染“行前准备”卡片。
   - 备选：直接删除字段与列。会造成前端/API 破坏性变更且需要数据迁移，收益不足，不采用。

## Risks / Trade-offs

- **共享缓存导致内容过期或不适合所有人** → 24 小时 TTL 限制陈旧窗口；键带版本号便于统一失效。
- **模型不按章节输出导致解析为空** → 解析失败视为生成失败并退费；抽屉提供重试。若仅部分字段缺失，则用空值降级，不阻塞整体展示。
- **缓存命中不展示“生成中”进度** → 直接返回完整内容，体验更快，符合预期。
- **并发锁期间用户体验为报错** → 返回可读提示「该国攻略正在生成，请稍后重试」，且通常数秒后缓存即可用。
- **移除行前准备可能让老用户找不到签证信息** → 国家抽屉的「旅游须知」承接该信息，并在发布说明中提示。

## Migration Plan

1. 先发布后端（新增接口、缓存、提示词；行程生成忽略 preparations），再发布前端。
2. 无数据库迁移；旧 `prep:*` 缓存键不再写入，24 小时内自然过期。
3. 回滚：后端回退后前端攻略区域调用失败时显示错误，不影响地图、抽屉与行程生成。
