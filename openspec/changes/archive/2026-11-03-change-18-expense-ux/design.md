## Context

见 `proposal.md`。记账页已有明细分页、国家/城市/旅行/分类/日期筛选、分组汇总与柱状图；后端 `ExpenseService.summary` 已能返回每组 CNY、分类小计与原币种明细。缺少的是按天全量视图、快捷录入、月度合计和分类占比图。

## Goals / Non-Goals

**Goals:**

- 降低高频记账的输入成本，同时不改变后端金额契约。
- 按天合计准确且不受分页影响。
- 复用现有汇总数据生成月度与分类视图，避免重复统计口径。

**Non-Goals:**

- 不改变汇率快照、负数冲减、多币种折算与筛选规则。
- 不新增自动汇率接口或实时汇率。
- 不把金额表达式发送到后端，也不支持变量、函数或单位换算。
- 不改变原有明细列表的分页与操作行为。

## Decisions

1. **新增 `GET /expenses/by-date` 返回全量分组**
   - 参数与明细列表一致：`countryCode`、`cityCode`、`tripId`、`ungrouped`、`category`、`from`、`to`。
   - 服务端查询全部匹配行，映射为现有 `Response`，按 `expenseDate` 倒序分组、组内按 ID 倒序。
   - 每组计算 `totalCny`（忽略 `amountCny` 为 null 的记录）与 `originalCurrencies`；响应顶层返回总 CNY 与未配置汇率币种。
   - 备选：前端用当前分页数据分组。每日合计会漏掉跨页记录，不采用。

2. **金额表达式只在前端解析**
   - 实现递归下降解析器，仅接受数字、`+ - * /`、括号与空格；先做字符白名单校验，再解析。
   - 结果使用 `toFixed(2)`；非有限值、除零、空表达式或超长输入 → 提示且不提交。
   - 表达式含运算符时在输入框下方实时显示计算结果；最终仍以 `amount` 字符串交给现有 API。
   - 备选：后端接收表达式。会扩大 API 契约并影响历史客户端，不采用。

3. **快捷偏好存 `localStorage`**
   - Key `tm_expense_prefs`，值为 `{countryCode,currency,category}`；读取时校验类型，损坏则回退默认。
   - 新增成功或保存成功后写入；编辑既有记录时不覆盖偏好，也不使用偏好覆盖行值。
   - 备选：存后端用户偏好。需要新表/接口，V1 收益不足，不采用。

4. **「明细 / 按日期」视图切换，默认明细**
   - 明细沿用现有表格与分页，避免破坏现有操作与测试。
   - 按日期视图调用新接口，用日期分组卡片展示当日 CNY、原币合计与明细；编辑/删除后重新加载当前视图。
   - 备选：直接替换为日期分组。会丢失分页并改变现有交互，不采用。

5. **月度合计复用 summary**
   - 月份选择器默认当前月；调用 `summary('date', {from: 月初, to: 月末, ...当前筛选})`。
   - 从分组 `totalCny` 求和得到月合计；从各分组 `originalCurrencies` 聚合原币合计。
   - 备选：新增月度接口。现有 summary 已足够，不新增。

6. **分类饼图复用 summary 分类小计**
   - 将 `summary.groups[].categories` 按分类聚合为 CNY 金额，渲染 ECharts 饼图；与柱状图共用同一份 `summary`，保证口径一致。
   - 空数据时清空并显示空状态。

## Risks / Trade-offs

- **按日期接口返回全量数据** → V1 个人数据量有限；后续数据量增大时可增加按月分页或服务端聚合。
- **表达式解析器边界** → 仅支持四则运算，明确提示不支持其他语法；非法输入一律阻止。
- **localStorage 偏好跨设备不生效** → 这是本机快捷录入的选择，且不影响编辑与后端数据。
- **月度合计与当前筛选叠加可能让用户困惑** → 卡片标题注明“当前筛选下”；默认无筛选时即全量本月。
- **两个图表同时渲染影响性能** → 仅在汇总卡片可见时渲染，并在窗口 resize 时统一 resize。

## Migration Plan

纯前端 + 一个只读查询接口，无数据库迁移。后端先发布新接口，前端再切换；回滚前端后旧页面仍可正常使用。
